## Implementation steps

1. Read `services/tasks/shopify/_product_sync_orchestrator.py` and
   `services/infra/shopify/product_sync_client.py` to see what is actually emitted today.
2. Build fixtures for four representative `ShopifyProductSyncItem` payloads:
   a. **create path** — a SKU with no existing Shopify match
   b. **update path** — a SKU matching one existing product
   c. **metafields** — a payload with two metafield entries
   d. **multi-location additive inventory** — two `inventory_adjustments` entries
3. Patch `execute_shopify_graphql` to record every `(operation_name, query, variables)` tuple
   instead of performing I/O, then run `sync_one_product_sync_item` for each fixture.
4. Assert the recorded tuples against inline expected values, capturing:
   - the **operation name**
   - the **full query string** (normalise only trailing whitespace — do not reformat)
   - the **complete variables dict**
   - the **call order**
5. Add a module docstring stating why the file exists and that it must not be edited to match new
   behaviour without explicit human approval.

## Test contract

The file must assert:

- **create path** — variant lookup → `productCreate` → `productVariantsBulkUpdate` → (metafields if present)
- **update path** — variant lookup → `productUpdate` → `productVariantsBulkUpdate`
- **metafields** go through `metafieldsSet` with namespace `custom` — *today's* behaviour
- **additive inventory** emits `inventoryAdjustQuantities` with `name: "available"`, and **never**
  `inventorySetQuantities`
- **no `media` argument** is present on `productCreate` / `productUpdate` today
- the exact call order per fixture
