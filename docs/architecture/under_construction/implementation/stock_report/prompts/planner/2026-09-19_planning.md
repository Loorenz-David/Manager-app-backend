## Test rules that bind every criterion row

1. **Outcomes at a public boundary** (charter rule 2, owner rule 2026-09-19). Each row gives an
   input and its one exact outcome: a return value or HTTP response, persisted state, an emitted
   event, or a call that crosses to an external system. Rows never assert which internal function
   ran, internal call counts, query text, private helpers or mocked internal collaborators. The D6
   statement-count row above stays: it is the owner's ratified requirement (D6), stated as an
   observable bound on the request.
2. **Tests share a database with other tests' leftovers.** Each xdist worker gets one database for
   the whole run, and within a run 23 existing test files leave about 819 rows in 37 tables that no
   later test removes. This was measured 2026-09-19 and includes `item_categories`, `items`,
   `execution_tasks` and task/step rows, each in its own throwaway workspace. So every criterion's
   fixture creates its own workspace and scopes every assertion to it. No row asserts a global
   total. A test of any code that scans across workspaces (the consistency check, repair, or
   anything else that does not filter by workspace) asserts only its own workspace's rows, and
   must hold with foreign rows present. Tests that commit clean up what they created.
3. The implementer is **Codex** in a fresh session per phase, working only from the phase file's
   Read-first list. Apply your doctrine's phase-sizing test with that reader in mind.
